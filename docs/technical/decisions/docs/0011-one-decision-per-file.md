# one decision per file, numbered, in the subject's folder.

**2026-09-03**

The log was one file, the shape [0006](0006-one-file-per-subject.md)
gave it when decisions were one subject. WritRun itself moved to a
folder — one entry per file, numbered, `README.md` as the
chronological index — and this repository mirrors its upstream's
conventions where it has no reason of its own. Append-only is
unchanged and cheaper to honour: a new decision is a new file, not an
edit to a file everything links to. **The number is identity**, on the
same rule the queue uses for tasks and specs: never reused, never
renumbered; a superseded decision keeps its file, and the entry that
replaces it names it. Entries sit in the folder of the technical
subject they concern — the taxonomy the `technical/` index already
fixes, so no new question of where a file goes. Rejected: keeping
`decisions.md` as a stub pointing at the folder (a file read once and
maintained forever).
